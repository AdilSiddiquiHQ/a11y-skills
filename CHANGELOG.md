# Changelog

All notable changes to this project are documented here. The format follows
[Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and this project
adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [0.3.2] — 2026-10-20

A measurement fix. One number in the README and the coverage report was counting a
claim instead of a test.

### Fixed

- **"Criteria with an executable fixture" was read from a hand-written label, not
  from what the fixtures assert.** Each fixture's `meta.json` records the criterion
  the case is *about*, and the coverage generator counted that field. For both
  `accessible-forms` cases the label says SC 3.3.2, but axe-core's `label` rule
  carries only SC 4.1.2 — so the report counted a criterion that nothing executes.
  The count now comes from each case's `expectRules`, looked up in
  `verify/axe-rules.json`. It was 9; it is 8. A number the person being counted can
  edit is not a measurement.
- **Three fixture cases assert best-practice rules only** — `landmark-one-main`,
  `region`, `heading-order` and `aria-dialog-name` carry no success criterion. They
  still prove their fix works, because `after.html` must be completely clean, but
  they cannot execute a criterion. `docs/COVERAGE.md` now reports them in their own
  row rather than folding them into the fixture count.

## [0.3.1] — 2026-10-19

A patch release with one behaviour fix that matters and one thing that was simply
missing.

### Fixed

- **`audit <directory>` no longer silently audits the wrong thing.** Handed a
  directory, it was passed to the browser as a `file://` URL, so Chromium rendered
  its own directory listing and the report described *that* — `landmark-one-main`,
  `region` — with no sign anything was wrong. It now exits 2 and prints how to
  audit every page. This mattered most via the GitHub Action, which documents
  directories as supported.
- **A nonexistent file exits 2, not 3.** Exit 3 means "a dependency is missing" and
  had been doing double duty.
- **The Action's shell no longer trips `set -u` on an empty array.** `"${extra[@]}"`
  is an unbound variable in bash 3.2 — the bash macOS ships — so anyone running
  the step's logic by hand on a Mac got an error instead of an audit.

### Changed

- **The Action's step body is `scripts/ci-audit.sh`**, not an inline `run:` block.
  Shell that only ever executes through `uses:` is untested shell; as a script it
  runs in the fixtures CI job, with assertions on the exit code, the
  `GITHUB_OUTPUT` values and the job summary.
- **Two `axe` runs per page instead of three.** A build output directory holds
  hundreds of files and each run launches a browser.
- `docs/ACTION.md` now documents the `wcag-only` and `summary` inputs and the
  `findings` and `without-skill` outputs, which were in `action.yml` and in no
  document.
- The fixtures CI job asserts that `audit` refuses a directory, and that
  `scripts/ci-audit.sh` exits 1 on a failing directory and 0 on a clean page while
  naming the skill that fixes the finding.

## [0.3.0] — 2026-10-19

The release that closes the loop. `0.2.0` was a library of procedures you had to
know to look for; this one takes an axe-core finding and tells you which procedure
to read, and covers **every Level A and Level AA success criterion in WCAG 2.2**.

### Added

- **`a11y-skills audit <file|url>`** — runs axe-core in a real Chromium and prints,
  for every finding, the skill that fixes it, the criteria the rule tests, and the
  first affected element with axe's own reason. `--json`, `--md` (for a CI step
  summary), `--wcag-only`, and `--fail-on critical|serious|moderate|minor|none`
  for the exit code. It reports how many findings have **no** skill behind them
  rather than implying full coverage, and how many results axe could not decide.
  It is the one command that needs dependencies; when they are missing it prints
  the exact install command and exits 3 instead of failing with a resolution error.
- **`a11y-skills rules [axe-rule]`** — the axe rule to skill map, offline: every
  rule with its skill, and for a single rule its help text, criteria, default
  enabled state, the skill to read, why, and the other skills that are also
  relevant.
- **`verify/rule-map.json`** — a curated primary skill for 99 of axe-core 4.14's
  105 rules, and **`docs/RULE-MAP.md`** generated from it, listing the six rules
  with no skill behind them and why each is absent.
- **`verify/axe-rules.json`** — a committed snapshot of axe-core's rules and the
  criteria each one tests, generated by `npm run axe-rules`. Committing it is what
  lets the content gate (and the mapping) be validated in a CI job with no
  dependencies installed.
- **Three skills**, taking the library to 33:
  - `semantic-html` — lists, definition lists and paragraphs styled as headings.
  - `pointer-and-gestures` — drag/swipe-only features, pointer-down activation,
    target size, and input devices being added or swapped.
  - `predictable-context` — context changes on focus and on input, consistent
    identification, and unsolicited reloads.
- **Three fixtures** (14 total) covering six rules that had no test before:
  `list`, `listitem`, `definition-list`, `dlitem`, `p-as-heading` and `target-size`.
- **`axeOptions` in a fixture's `meta.json`**, so a rule axe ships disabled can be
  enabled and actually tested. `target-size` (SC 2.5.8) and `p-as-heading` are both
  off by default, so before this a fixture naming either would have passed while
  testing nothing.
- **A GitHub Action** ([`action.yml`](action.yml), documented in
  [`docs/ACTION.md`](docs/ACTION.md)) — audits a file, a directory of built HTML or
  a URL, writes the report to the job summary, and fails on `--fail-on`.
- **`lib/chromium.js`**, so the fixture harness and the CLI agree on what a usable
  browser is, without `bin/` acquiring a dependency.

### Changed

- **Criterion coverage from 52 to 70 of 86**, which is **100% of Level A (31 of
  31) and 100% of Level AA (24 of 24)**. Level AAA went from 8 to 15 of 31.
- **Nine skills gained criteria they should always have covered**, each with a real
  procedure rather than a citation: `keyboard-focus` (SC 2.1.3, SC 2.1.4),
  `zoom-reflow-text-spacing` (SC 1.3.4, SC 1.4.5), `accessible-forms` (SC 4.1.2,
  SC 3.3.4), `accessible-authentication` (SC 2.2.6), `accessible-name` (SC 1.3.6),
  `forced-colors-and-dark-mode` (SC 1.3.3), `motion-and-animation` (SC 2.3.2),
  `pagination-and-search` (SC 2.4.5) and `fix-color-contrast` (SC 1.4.6).
- **The coverage backlog is empty.** The 16 criteria with no skill are all ones no
  design procedure can satisfy — sign language interpretation, reading level, "no
  timing" — and the coverage report says so per criterion.
- `verify/verify-readme.js` now also pins the rule-map count, so the README's
  "99 of 105 axe rules" cannot drift either.
- The README is rewritten around the audit loop; `docs/ARCHITECTURE.md` and
  `AGENTS.md` describe the new layer and the axe-core behaviours that are easy to
  get wrong.

### Fixed

- **Four wrong mappings**, caught by the rule-map validator before they shipped: it
  requires the mapped skill to declare one of the criteria axe tags the rule with,
  and `color-contrast-enhanced`, `label`, `select-name` and `css-orientation-lock`
  all pointed at a skill whose criteria line did not cover them. Three skills
  gained the criterion they genuinely should have had; the fourth was mapped to the
  right skill.

## [0.2.0] — 2026-10-18

The expansion from a starter set to something you can actually rely on: 6 skills
to 30, and — more importantly — the fixtures that prove the advice works.

### Added

- **24 new skills**, taking the library from 6 to 30 and criterion coverage from
  18 to 52 of the 86 criteria in WCAG 2.2. New ground: dialogs, tabs,
  accordions, comboboxes, menus, tooltips, carousels, data tables, charts,
  live regions, progress and loading, pagination, headings and landmarks, page
  title and language, zoom and reflow, motion, forced colours, skip links,
  authentication, media, SVG and icons, email, screen-reader test plans, and
  triage of automated results.
- **Executable fixtures** (`verify/fixtures/`, 11 cases) — each a
  `before.html` that must trip the named axe-core rules and an `after.html` that
  must be completely clean. Run with `npm run fixtures`, in a real Chromium
  because contrast cannot be computed without layout.
- **`docs/COVERAGE.md`** and a generated coverage badge — criterion-by-criterion,
  with the criteria that are deliberately absent and why.
- **Generated `skills/README.md`** with a derived criterion-to-skill map, so the
  index cannot disagree with the skills.
- **CLI**: `search`, `info`, `criteria`, and `--json` on all of them, plus
  `--no-color` (and the `NO_COLOR` / `FORCE_COLOR` environment variables).
- **`docs/demo.gif`** and `scripts/make-demo.mjs` — the demo is built from a real
  fixture by running axe-core and outlining what it found; the script refuses to
  build if the "after" fixture has violations.
- **`docs/cli.gif`** and `scripts/make-cli-demo.mjs` — the terminal demo runs the
  real CLI, captures its real stdout, and renders it, sized to the output so that
  nothing is clipped to make the demo look tidier. No pty, no Python, no
  committed mystery binary.
- Project hygiene: `docs/AUTHORING.md`, `docs/ARCHITECTURE.md`, `AGENTS.md`,
  `SECURITY.md`, `CODE_OF_CONDUCT.md`, `CITATION.cff`, issue and pull request
  templates.
- CI: a fixtures job that installs Chromium and asserts every pair, a
  generated-docs freshness check, and a check that `--json` output parses.

### Changed

- `verify/verify-skills.js` now regenerates the index and the coverage report and
  fails if either differs, instead of only checking that the index mentions each
  skill. The weaker check passed when a skill was renamed in the index but not in
  the directory, which is how a curated list actually rots.
- `verify/verify-readme.js` also pins the coverage claims in the README, so the
  headline number cannot drift from the skills.
- The fixture harness asserts a **completely clean** `after.html`, including
  best-practice rules, rather than only the rule under test.
- Dependencies: the skills and the CLI are still zero-dependency; fixtures and
  the demo use axe-core and Playwright as devDependencies only.

## [0.1.0] — 2026-10-17

Initial release.

### Added

- Six skills: `audit-component`, `fix-color-contrast`, `keyboard-focus`,
  `accessible-name`, `accessible-forms`, `wcag22-new-criteria`.
- `verify/wcag-2.2.json` — all 86 WCAG 2.2 success criteria, their levels, and
  the criteria added in 2.1 and 2.2, plus the one removed in 2.2.
- `verify/verify-skills.js` — checks frontmatter, required sections, every
  criterion citation against the spec, and index freshness.
- `verify/verify-readme.js` — pins the README's sample output to the real output.
- `bin/a11y-skills.js` — a zero-dependency `list` and `install` CLI.
- CI running the verifier, the installer, and a SkillSleuth scan of this
  repository's own skills.
